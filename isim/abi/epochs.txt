# Binaries whose ABI broke on purpose: "<binary path in the SDK> <version>". Baselines older than <version> are not
# checked for that binary; apps built with an older isim that use it must be rebuilt.
# Breaking is fine when keeping the old ABI would need a large workaround or a lot of compatibility code: clean code
# and one rebuild beat carrying shims (AGENTS.md, "ABI stability"). Breaks ship in a minor or major release.
#
# 0.12.0 (issue #38): the base Swift overlays are built with library evolution, like Apple's. Before, about 50 resilient
# overlays (SwiftUI, AVFoundation, ...) depended on these fragile ones, so a layout change in them could silently break
# apps. Their symbols changed shape (resilient accessors instead of addressors, field offsets and witness tables).
usr/lib/swift/libswiftObjectiveC.dylib 0.12.0
usr/lib/swift/libswiftDispatch.dylib 0.12.0
usr/lib/swift/libswiftFoundation.dylib 0.12.0
usr/lib/swift/libswiftUIKit.dylib 0.12.0
usr/lib/swift/libswiftCoreGraphics.dylib 0.12.0
# 0.20.0 (issue #25): isim no longer ships stand-ins for third-party SDKs: it re-implements Apple's iOS SDK only
# (AGENTS.md, "Only Apple's SDK"). The Google Mobile Ads and User Messaging Platform stand-ins are gone; apps that
# linked them must be rebuilt against the real SDKs (isim build fetches their packages).
# 0.22.0 (issue #206): the 0.20.0 and 0.21.0 release builds restored out/ from CI's cache, which still held the removed
# stand-ins, so those tarballs and their ABI baselines still had them. The build now removes SDK binaries the graph no
# longer builds (build.py ci); apps that linked the stand-ins must be rebuilt with 0.22.
usr/lib/swift/libswiftGoogleMobileAds.dylib 0.22.0
usr/lib/swift/libswiftUserMessagingPlatform.dylib 0.22.0
# 0.20.0 (issue #200): WebKit for Objective-C. The overlay's classes took Apple's Objective-C names and their members are
# dispatched through objc_msgSend (`@objc dynamic`, or final), so Objective-C code and binary SDKs can subclass them (an
# Objective-C subclass has no Swift vtable); the delegate methods use Apple's selectors (webView:didFinishNavigation:...).
# Swift apps that use WebKit must be rebuilt with 0.20 (the old class symbols are kept as aliases, the vtable thunks are not).
usr/lib/swift/libswiftWebKit.dylib 0.20.0
# 0.23.0 (issue #227): SwiftData was a stub (an in-memory dictionary, Schema an enum namespace); it now has Apple's
# shapes: Schema is a class, ModelConfiguration carries a schema, PersistentModel refines Identifiable / Hashable /
# Observable, fetches filter and sort. Swift apps built with 0.22 or earlier that use SwiftData must be rebuilt.
usr/lib/swift/libswiftSwiftData.dylib 0.23.0
